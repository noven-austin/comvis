# Model Comparison — Semaphore Translation
_Generated by `compare_models.py`. 3 runs per model._

## TL;DR

- **Best test accuracy**: `LSTM` (99.96% ± 0.05)
- **Fastest inference**: `DNN` (8.02 ms / sample)
- **Smallest model**: `DNN` (58.1 KB)

## Methodology

Three classifiers are trained and evaluated under a matched, group-aware partition of the source frames. The group is the `source_id` (original raw-frame index) — identical to the strategy in `train_model.py`. The same source frames go to the same side of the partition for all three models per run, so any accuracy differences are attributable to the model itself, not to partition luck or augmentation leak. All three models use `class_weight='balanced'` to handle the ~2.6× imbalance between the most and least frequent letters.

- **DNN** — 24-dim per-frame features → `128-64-32` MLP with BatchNorm + Dropout(0.2). Trained on `poses_augmented.csv`.
- **Random Forest** — 24-dim per-frame features → 300 trees, `class_weight='balanced'`. Trained on `poses_augmented.csv`.
- **LSTM** — sequences of length 10 (= 1.0s at 10 fps) → `LSTM(64)` → `Dense(32)` → softmax. Sequences extracted from `poses_raw.csv` and augmented with the same primitives used for the DNN/RF data. Per-frame joint noise is drawn independently within each window — the LSTM has to learn to smooth it. Each window's group is the `source_id` of its center frame.

- **Runs**: 3 different group-split seeds. Numbers below are mean ± std.
- **Latency**: single-sample wall-clock on CPU, averaged over 1000 calls after 100 warmup calls.

### Caveat on LSTM splitting

Each LSTM window's group is the `source_id` of its CENTER frame, but a window of length 10 spans 10 source IDs and the next window (stride 3) shares 7 of them. So two windows can land on opposite sides of the split while sharing most of their underlying frames. This means LSTM test accuracy may be modestly inflated by frame-level overlap between adjacent train/test windows. Per-frame independent joint noise in the augmentation provides real diversity that mitigates this, but the LSTM number should be read as a slight upper bound. A stricter alternative would group windows by entire video, but with only 27 videos that would put whole letters into test and make per-class numbers meaningless.

## Discussion

### Q1 — Is a DNN justified vs Random Forest on 24-dim features?

DNN scored 99.83% vs Random Forest 99.87% — a gap of **-0.04** percentage points. At inference, DNN takes 8.02 ms vs RF's 47.45 ms per sample. Interpret in light of the std bands above: if the gap is smaller than the sum of the two stds, the difference is not statistically meaningful at this sample size.

### Q2 — Native temporal (LSTM) vs static DNN + smoothing?

LSTM scored 99.96% on whole-window classification vs DNN's per-frame 99.83% (gap **+0.13** pp). LSTM latency is 26.87 ms/window vs DNN's 8.02 ms/frame.

A key caveat: the deployed DNN already has temporal smoothing at inference (mode over a 180-frame window, COMMIT_AFTER=30). The fairest live-equivalent comparison would aggregate DNN per-frame predictions across a window of the same length the LSTM sees, then compare to LSTM window predictions. That extension is left as future work. Also see the windowing caveat above — the LSTM number is a slight upper bound due to adjacent-window frame overlap.
